# Luna Beauty — օնլայն կոսմետիկայի խանութ

Սա frontend + Supabase backend տարբերակն է։ Կայքը կարող է հրապարակվել GitHub Pages-ում, իսկ ապրանքները, պատվերներն ու ադմինիստրատորի մուտքը կառավարվում են Supabase-ի միջոցով։

## Ինչ կա նախագծում
- Ապրանքների կատալոգ, որոնում և կատեգորիաների ֆիլտրեր
- Զամբյուղ, քանակի փոփոխում և պատվերի ձև
- Պատվերների պահպանում Supabase տվյալների բազայում
- Ադմինի մուտք, պատվերների դիտում և կարգավիճակի փոփոխում
- Ապրանքների ավելացում, խմբագրում և ջնջում
- Responsive դիզայն՝ հեռախոսի և համակարգչի համար

## Քայլ 1. Բացել VS Code-ում
1. Արխիվը բացիր քո համակարգչում։
2. VS Code → File → Open Folder → ընտրիր `luna-beauty-store` պանակը։
3. Տեղադրիր Live Server extension-ը, եթե ուզում ես տեղում փորձարկել։
4. `index.html`-ի վրա աջ click → Open with Live Server։

Մինչև Supabase-ը միացնելը կայքը ցուցադրում է demo ապրանքներ, բայց պատվերներն ու ադմինի գործառույթները չեն աշխատի։

## Քայլ 2. Ստեղծել Supabase backend
1. Բացիր https://supabase.com և գրանցվիր։
2. Ստեղծիր նոր project, ընտրիր ուժեղ database password և պահիր այն ապահով տեղում։
3. Project-ի ներսում բացիր **SQL Editor → New query**։
4. Այս պանակի `supabase.sql` ֆայլի ամբողջ պարունակությունը պատճենիր SQL Editor և սեղմիր **Run**։
5. Բացիր **Project Settings → API** (որոշ տարբերակներում՝ Connect)։
6. Պատճենիր Project URL-ն ու anon/publishable key-ը։
7. Բացիր `config.js` և փոխարինիր `PASTE_YOUR_SUPABASE_PROJECT_URL_HERE` ու `PASTE_YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY_HERE` արժեքները քո արժեքներով։

**Կարևոր․** երբեք մի տեղադրիր `service_role` կամ secret key-ը frontend կոդի մեջ։ Հանրային anon/publishable key-ը նախատեսված է browser-ի համար, իսկ անվտանգությունը ապահովում են RLS քաղաքականությունները։

## Քայլ 3. Ստեղծել ադմինիստրատորի հաշիվ
1. Supabase → **Authentication → Users → Add user**։
2. Մուտքագրիր քո email-ը և ուժեղ գաղտնաբառը։ Եթե կա Confirm email տարբերակ, փորձարկման համար կարող ես հաստատել օգտվողին dashboard-ից։
3. Պահպանիր օգտվողին։
4. Բացիր **SQL Editor → New query** և աշխատեցրու սա՝ քո նոր օգտվողի իրական email-ով.

```sql
insert into public.admin_users (user_id)
select id from auth.users where email = 'YOUR-ADMIN-EMAIL@example.com'
on conflict (user_id) do nothing;
```

Փոխիր `YOUR-ADMIN-EMAIL@example.com`-ը քո email-ով և Run արա։ Միայն այդ աղյուսակում ավելացված օգտվողը կունենա ադմինի իրավունք։ Մի՛ ստեղծիր հանրային գրանցման էջ ադմինի համար։

## Քայլ 4. Փորձարկել
1. Refresh արա կայքը Live Server-ում։
2. Ստուգիր՝ ապրանքները բեռնվում են Supabase-ից։
3. Ավելացրու ապրանք զամբյուղ, լրացրու պատվերի տվյալները և հաստատիր։
4. Սեղմիր **Ադմին**, մուտք գործիր ստեղծած email-ով ու գաղտնաբառով։
5. «Պատվերներ» բաժնում պետք է երևա պատվերը։ Փոխիր կարգավիճակը։
6. «Ապրանքներ» բաժնից ավելացրու կամ խմբագրիր ապրանք։

## Քայլ 5. Հրապարակել GitHub Pages-ում
1. GitHub-ում ստեղծիր նոր repository՝ `luna-beauty-store` անունով։
2. Բեռնիր `index.html`, `style.css`, `app.js`, `config.js` և մյուս ֆայլերը repository-ի **root** մակարդակում (ոչ թե ներսում երկրորդ ենթապանակում)։
3. Բացիր repository → **Settings → Pages**։
4. **Build and deployment** բաժնում ընտրիր **Deploy from a branch**։
5. Branch ընտրիր `main`, folder՝ `/(root)`, հետո **Save**։
6. Սպասիր, մինչև GitHub Pages-ը հրապարակվի։ Հղումը սովորաբար կլինի `https://YOUR-USERNAME.github.io/luna-beauty-store/`։

Եթե repository-ն public է, `config.js`-ում URL-ն ու anon/publishable key-ը տեսանելի կլինեն կայքի այցելուներին․ դա սպասված է browser app-ի համար։ Տվյալների անվտանգությունը կախված է RLS քաղաքականություններից, ուժեղ admin գաղտնաբառից և Supabase կարգավորումներից։

## Իրական աշխատանքի կարևոր սահմանափակումներ
- Այս starter տարբերակը պատվերի տվյալները պահպանում է Supabase-ում, բայց **առցանց վճարում չի ընդունում**։ Վճարման համար պետք է միացնել համապատասխան վճարային համակարգ։
- Առաքման գինը, առաքման ժամկետները, վերադարձի պայմանները և գաղտնիության քաղաքականությունը պետք է լրացնել քո իրական բիզնեսի տվյալներով։
- Պատվերի գումարը և ապրանքների ցանկը այս պարզ տարբերակում ուղարկվում են browser-ից։ Մինչև իրական վճարումներ/մեծ ծավալի վաճառք գործարկելը, պետք է պատվերի գինը վերահաշվարկել վստահելի backend/Edge Function-ում և ավելացնել հակասպամ պաշտպանություն։
- Մի հրապարակիր իրական հաճախորդների տվյալներ demo-ի համար։ Պատվերների տվյալները անձնական տվյալներ են․ օգտագործիր դրանք միայն պատվերը կատարելու նպատակով։
